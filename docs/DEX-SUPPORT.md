# DEX recognition and execution boundaries

There are three different questions: can saved source evidence be classified,
can a provider return a route label, and can a follower transaction satisfy an
independent execution review? An affirmative answer to one does not establish
the next. This table describes the checked-in source, not present pool access
or current mainnet qualification.

| Protocol / format                                        | Source instruction and classification layer                                                                                                                                                                                                                                                   | Provider quote label layer                                                                                                       | Historical execution / review layer                                                                                                                                                                                                             |
| -------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Jupiter JUP6, older instruction forms                    | The byte decoder enumerates `route`, `route_with_token_ledger`, `shared_accounts_route`, `shared_accounts_route_with_token_ledger`, `exact_out_route`, `shared_accounts_exact_out_route`. Classification additionally requires supported signer, owner-scoped asset deltas and swap evidence. | The adapter retains a provider route array. A returned AMM label is metadata, not a local instruction decoder or qualified pool. | Independent review has narrow V1 single-route and limited captured V2 shapes. It rejects unsupported outer programs/account shapes; it is not the same acceptance set as source classification.                                                 |
| Jupiter `route_v2` / `shared_accounts_route_v2`          | Not enumerated by the general byte decoder. Parsed instruction text or logs may contribute evidence, but that is not full V2 layout, root or owner proof. No universal multi-intent reconstruction is claimed.                                                                                | Receiving either format or label from a provider does not add source decoding support.                                           | A separate limited `route_v2` branch exists in historical review; its ABI evidence is explicitly capture-corroborated, not first-party IDL. This does not imply `shared_accounts_route_v2` or generic V2 support.                               |
| Raydium AMM v4                                           | The known AMM program maps to `RAYDIUM`; byte opcodes `9` / `11` decode as `swapBaseIn` / `swapBaseOut`. Supported asset evidence can then classify direction.                                                                                                                                | Provider labels can name Raydium venues, including different programs.                                                           | Source AMM classification does not authorize AMM execution or stand in for CLMM program/account evidence.                                                                                                                                       |

| Pump.fun                                                 | Limited byte names: `buy`, `sell`, `buy_exact_sol_in`; classifier still applies all ordinary evidence checks.                                                                                                                                                                                 | Labels do not establish version, bonding-curve state or executable accounts.                                                     | No Pump.fun live execution scope is established by this decoder or demo.                                                                                                                                                                        |

## Evidence and limits

The source registry is [program-registry.ts](../src/decoder/program-registry.ts),
and its byte decoder is [instruction-decoder.ts](../src/decoder/instruction-decoder.ts).
[Instruction tests](../test/unit/instruction-decoder.test.ts) exercise selected
Anchor names and both AMM v4 swap opcodes;
[fixture tests](../test/fixtures/decoder-fixtures.test.ts) exercise classification.
Tests of a name or opcode do not prove a complete instruction/account layout.

The [swap evidence validator](../src/decoder/swap-evidence-validator.ts) can use
parsed type or logs as well as decoded bytes. The first recognized DEX is not a
full hop inventory. [SwapClassifier](../src/decoder/swap-classifier.ts) produces
one supported asset-delta event with `eventIndex=0`; it does not generally split
every economic intent in a signature or turn AMM legs into separate BUYs.

The historical [quote adapter](../src/execution/jupiter-order-adapter.ts) retains
`routePlan` entries as unknown provider data. Its successful parsing does not
prove pool ownership, programs, executable depth, actual fill or anti-MEV
protection. No quote endpoint is invoked by the public demos.

Historical [transaction review](../src/live/transaction-review.ts) has a separate
boundary. The public `demo:review` example uses synthetic unsigned bytes and
expects rejection for missing independent CPI evidence. It demonstrates selected
checks rather than a successful qualified transaction. No policy, allowlist or
funds authority is widened. See [CAPABILITIES.md](CAPABILITIES.md) and
[OPEN_SOURCE.md](OPEN_SOURCE.md) before interpreting a `dex` field as support.
